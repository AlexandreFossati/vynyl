# product-database-schema Specification

## Purpose

Define the relational structure and the integrity guarantees of the products table, versioned in reproducible migrations, so that any data access layer can rely on the database as the last line of defense.

## Requirements

### Requirement: Products table structure
The database SHALL have the `products` table with the columns: `id` (integer, primary key with auto-increment), `title`, `description`, `category`, `price_cents` (integer), `stock` (integer), `brand`, `sku`, `weight` (real number), `created_at` and `updated_at` (text). All columns SHALL be required, except `id`, which is generated by the database.

#### Scenario: Valid insertion generates an identifier
- **WHEN** a product with all required fields is inserted without providing `id`
- **THEN** the database assigns a positive, increasing integer `id`

#### Scenario: Missing required field
- **WHEN** an insertion omits any required column (except `id`, `created_at` and `updated_at`)
- **THEN** the database rejects the insertion

### Requirement: SKU uniqueness
The database SHALL guarantee that each product's `sku` is unique.

#### Scenario: Duplicate SKU is rejected
- **WHEN** a product is inserted whose `sku` already exists in the table
- **THEN** the database rejects the insertion with a uniqueness violation and the table remains unchanged

### Requirement: Numeric value constraints
The database SHALL reject values outside the business limits: `price_cents` MUST be greater than or equal to 0, `stock` MUST be greater than or equal to 0 and `weight` MUST be greater than 0.

#### Scenario: Negative price
- **WHEN** a product is inserted or updated with `price_cents` less than 0
- **THEN** the database rejects the operation

#### Scenario: Negative stock
- **WHEN** a product is inserted or updated with `stock` less than 0
- **THEN** the database rejects the operation

#### Scenario: Zero or negative weight
- **WHEN** a product is inserted or updated with `weight` less than or equal to 0
- **THEN** the database rejects the operation

#### Scenario: Boundary values accepted
- **WHEN** a product is inserted with `price_cents` equal to 0, `stock` equal to 0 and `weight` greater than 0
- **THEN** the database accepts the insertion

### Requirement: Index on category
The database SHALL have an index on the `category` column to support filtering by category.

#### Scenario: Index present
- **WHEN** the database structure is inspected after applying the migrations
- **THEN** there is an index on `products.category`

### Requirement: Default timestamps
When `created_at` and `updated_at` are not provided on insertion, the database SHALL fill them with the current instant in UTC in ISO 8601 format with milliseconds and the `Z` suffix (for example, `2025-04-30T09:41:02.053Z`).

#### Scenario: Insertion without timestamps
- **WHEN** a product is inserted without `created_at` and `updated_at`
- **THEN** both are filled with a text in ISO 8601 UTC format with milliseconds and the `Z` suffix

#### Scenario: Insertion with explicit timestamps
- **WHEN** a product is inserted providing `created_at` and `updated_at`
- **THEN** the provided values are preserved unchanged

### Requirement: Versioned and reproducible migration
The database structure SHALL be created exclusively by SQL migrations versioned in the repository at `apps/api/drizzle/`. Applying all migrations to an empty database SHALL produce the complete structure described in this capability. The `db:generate` script SHALL generate new migrations from the schema and SHALL NOT produce changes when the schema and the migrations are in sync.

#### Scenario: Empty database receives the complete structure
- **WHEN** the migrations are applied to an empty SQLite database
- **THEN** the `products` table exists with columns, constraints, uniqueness and index as per this capability

#### Scenario: Schema and migrations in sync
- **WHEN** the developer runs `npm run db:generate -w apps/api` without having changed the schema
- **THEN** the command reports there are no changes and no new file is created
